# 设计决策

记录 CCGuard 的主要取舍。日期是做出决定的日期；细节与验证见 [CHANGELOG](../CHANGELOG.md)。

## D1 只读、监测不联网（2026-11-15）

监测只读本机状态，不修改防火墙、路由、代理配置，不需要管理员。10 项检查不发起任何出站请求，所以可以长期开着，也不会把机器信息发给任何人。查询失败、权限不足或数据缺失一律记为“未知”，不推测为正常。

## D2 状态与日志不含 IP 和路径（2026-11-17）

状态文件会交给托盘和本地网页，检测日志也会显示在界面上，所以只写进程名、网卡名、数量和判定结论，不写 IP 地址和文件路径；测试强制检查。检测日志在判定处同时生成，不另写一套解释，避免日志和判定不一致。

## D3 WebView 面板，tkinter 回退（2026-11-17）

tkinter 的外观和刷新性能达不到要求，默认面板改用 pywebview + Edge WebView2（Windows 10/11 自带）。页面只经 JS 桥接调用 Python，不开端口、不发网络请求。pywebview 或 WebView2 不可用时自动回退 tkinter 面板。pywebview 在界面线程上同步执行 `closing` 回调，回调里不能等待页面，否则窗口卡死。

## D4 中文字体（2026-11-17）

界面几乎全是中文，正文必须用有完整中文字形的字体，否则逐字回退、同一行混用两种字体。安装版打包 Noto Sans SC（OFL），各机一致；Python 运行时按已安装字体选，最低回退到 Windows 自带的 Microsoft YaHei UI。字体在构建时从固定提交下载并校验哈希，不进 git。

## D5 联网功能只在点击时运行（2026-11-17）

出口评分和检查更新是仅有的联网功能，都只在用户点击时运行，只联系固定地址（Cloudflare `1.1.1.1/cdn-cgi/trace`、`ip.net.coffee/api/iprisk`、GitHub 本仓库发布列表），从不访问 claude.ai 或 anthropic.com。ip.net.coffee 的完整检测页会从浏览器测 Claude 的可用性，所以面板只在用户的默认浏览器里打开它，自己不加载。出口评分评的是 Cloudflare 看到的出口，代理规则让 claude.ai 走不同节点时以浏览器页为准。界面只显示 IP 前两段，评分结果不落盘。

## D6 安装程序在 CI 上构建（2026-11-17）

用户不必安装 Python。PyInstaller 文件夹版（启动快，误报少于单文件版）+ Inno Setup 按当前用户安装，不需要管理员。安装程序由 GitHub Actions 从源码构建，附到 Release 前做静默安装、自检、卸载验证，任何人都能对照源码和构建记录。未做代码签名（证书是付费服务，需另行确认），README 写明 SmartScreen 的放行方法和哈希核对。

## D7 版本号与更新（2026-11-17）

版本号只写在 `scripts/version.py`，发布标签不一致时构建失败。检查更新只列出新版本和说明，由用户在浏览器里下载安装程序；不做自动下载和安装，因为安装程序没有签名，静默替换程序风险较高。面向用户的更新日志随程序打包，必须与版本号同步更新。

## D8 独立仓库（2026-11-17）

CCGuard 最初在一个 Skill 仓库的 fork 中开发，但代码只依赖标准库和 pywebview，不用 Skill 的其他部分；共用仓库让每次改动都要跑与 CCGuard 无关的测试和 macOS 作业。经用户决定拆为独立仓库，保留 CCGuard 文件的提交历史，CI 只跑 Linux 与 Windows。
